# Goal 5 — Catalog coverage and scale

## Catalog tiers

| Tier | Definition | Status |
|---|---|---|
| C0 | Frozen Goal 4 catalog: 49,620 selected, 49,195 canonical structures | preserved regression control |
| C1 | Every canonical, unique structure in the complete Kaggle train | implemented and built in the private Goal 5 run |
| C2 | C1 + COCONUT | researched; not imported in Goal 5 |
| C3 | progressive licensed sources / fixed PubChem subset | design only |

C1 is the required verified expansion for this goal.  It is generated by
streaming only structure metadata from the full train Parquet; MS/MS arrays are
not materialized during catalog construction.  Website or competition-summary
counts are never substituted for the count emitted after RDKit parsing,
tautomer canonicalization and InChIKey14 deduplication.

### C1 misurato

Il build recuperato dal run privato v2 contiene **271.439** strutture canoniche
uniche e **50.662** formule uniche, con RDKit 2026.03.3 e 11 sorgenti train.
Gli array checksummed occupano **34.821.876 byte** non compressi. Il manifest e
gli array sono conservati sotto
`artifacts/goal5_kaggle_v2/goal5/c1_mass_formula_index/`; il manifest identifica
il tier come `C1_train_unique` e registra hash, dtype, shape e byte count di ogni
file.

Questo è un risultato di costruzione e storage, non una misura di candidate
coverage: Recall@25/100/1000 su C1 non è ancora disponibile. Il run v2 ha
speso circa 43.084 s (11 h 58 min) nella canonicalizzazione e ha raggiunto il
limite del worker. Riutilizzare l'indice persistente evita di ripetere questo
costo; futuri rebuild completi vanno eseguiti sulla VM esterna.

## C1 construction contract

For each declared training identity the builder retains source provenance and
observed structural conflicts, then derives from one canonical RDKit molecule:

- tautomer-canonical InChIKey14;
- canonical isomeric SMILES;
- exact monoisotopic mass;
- molecular formula.

Rows are rejected rather than silently repaired when the declared InChIKey14
does not match the canonical structure.  Reports contain missing-SMILES,
invalid-identity, invalid-structure, identity-mismatch, formula-mismatch and
conflicting-record counts.  Physical holdout exclusion occurs before a record
can enter an index.

## Index architecture

`ScalableMassFormulaIndex` stores:

- exact masses sorted ascending;
- compact fixed-width identity and formula arrays;
- formula posting lists;
- UTF-8 blobs plus offsets for SMILES and provenance;
- a schema-versioned manifest with SHA-256, dtype, shape and byte count for
  every array.

Loading uses NumPy memory mapping.  Exact mass range lookup is
`O(log N + k)` through `searchsorted`; nearest-mass fallback uses `argpartition`
and deterministic identity tie-breaking.  The index supports batching, an LRU
cache with defensive copies, dynamic ppm windows and a fixed cap for expensive
reranking.

FAISS/HNSW was deliberately not added.  A one-dimensional exact mass query is
not an ANN problem, and approximation would introduce recall risk without
addressing a measured bottleneck.  ANN remains appropriate only if a future
fingerprint or DreaMS vector channel is shown to dominate runtime.

## Retrieval experiments

The Goal 5 artifact compares:

- E7: frozen E6 logic on C0;
- E8: same logic on expanded C1 with the legacy brute mass selector;
- E9: E8 with the new exact index; ordered candidates must match E8 exactly;
- E10: C1 with a 5/10/20/50 ppm dynamic pool, nearest-mass fallback, cap 1,000,
  cheap head 300 and expensive E6 head 100;
- E11: not run because no database prior was both inference-safe and
  independently justified;
- E12: weighted RRF union of exact-mass and reference-analog candidate channels,
  with the original nearest-mass anchor retained for E6.

Candidate Recall@25/100/1000, pool recall, MRR@25, conditional MRR, oracle MRR,
same-formula errors, paired transitions, time and memory are recorded separately
for A/B/C and development/sealed stages.  This prevents a larger catalog's
coverage gain from being confused with ranking dilution.

## Storage and licensing decision

C1 is derived from competition data and is attached only to the private run.
No external dump was downloaded or redistributed.  COCONUT or LIPID MAPS may
enter C2 only with raw URL/date/hash/license provenance and a post-canonical
overlap report.  PubChem must not be scraped using hidden-test masses and must
not be materialized in full inside a Kaggle notebook.
